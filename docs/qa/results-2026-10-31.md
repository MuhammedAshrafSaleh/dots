## Pre-run issues found (infrastructure, not app bugs)

### 1. Missing DB migration — `coupon_redemptions.released_at`

Migration `2026_10_27_081951_add_released_at_to_coupon_redemptions_table` was **Pending** before this run.  
The column exists in the migration but had never been applied to the local `dots` database.  
**Fix applied during this session:** `php artisan migrate` — the column now exists and the CP tests pass.  
**Action needed:** Ensure this migration is applied in any environment that hasn't had it run (staging, production, other developer machines). It is not destructive — it adds a nullable `released_at` timestamp to `coupon_redemptions`.

### 2. SN-04 — notice detection was a test false negative; notice works correctly

The `pf_expired_readd_none` notice IS set and flashed. `PaymentFailed::reAddToCart()` calls `session()->flash('cart_notices', ...)` before the Livewire `navigate: true` redirect; `site/cart.blade.php` renders those notices at the top of the page on the redirected load. The translated text starts with capital "**N**one of the items…", and the test checked `resBody.includes('none')` (lowercase) — so the notice was present but undetected. My earlier note "Currently no notice is shown" was incorrect. The `pf_expired_readd_none` path added in PAY.1 is working.

## Classification: real bugs vs test-setup problems

All 22 cases pass after the migration was applied. No cases remain as real application bugs based on automated assertions.

### What was a **test-setup problem** (resolved):
- CP-01/02/05 DB exceptions → pending migration `released_at` not run. Fixed by `php artisan migrate`.
- Mass checkout failures (MN, BK, PV, SN, LO groups) → IP-based rate limit (10 placements / 10 min) exhausted by earlier test cases. Fixed by calling `RateLimiter::clear('checkout.127.0.0.1')` between test groups.
- PV-04 rate-limit text not detected → English translation "Too many submissions." not matched by the original regex. Fixed by updating the pattern.
